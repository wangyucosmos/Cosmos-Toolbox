## 1. 调查结果：独立业务窗口（10 处 `NSWindow(`）

## 2. 逐窗口接线方案（第二批照着改）

通用替换模板（每个 Manager 的 `NSWindow(...)` 到 `window.delegate = self` 之间的约 8–15 行）：

```swift
let window = CosmosWindowFactory.makeWindow(
    CosmosWindowConfiguration(
        title: <原 window.title>,
        contentSize: NSSize(width: <原 contentRect 宽>, height: <原 contentRect 高>),
        minSize: <原 window.minSize>,
        identifier: <原 window.identifier 字符串>,
        allowsFullScreen: <原是否 insert(.fullScreenPrimary)>,
        delegate: self
    ),
    rootView: <原 rootView>
)
// 保留：let controller = NSWindowController(window: window); controllers[key] = controller; controller.showWindow(nil) 等
```

注意：工厂内部已 `center()`，原有 `window.center()` 删除（保留会重复居中，无害但冗余）；`isReleasedWhenClosed = false` 已由工厂设置，原有同名语句可删；**`NSWindowController.showWindow` / `makeKeyAndOrderFront` / `NSApp.activate` 保留在调用方**。

## 3. 工厂 API 与约定

```swift
struct CosmosWindowConfiguration {
    var title: String; var contentSize: NSSize; var minSize: NSSize
    var styleMask: NSWindow.StyleMask   // 默认含 .fullSizeContentView
    var toolbarStyle: NSWindow.ToolbarStyle      // 默认 .unified
    var titleVisibility: NSWindow.TitleVisibility // 默认 .visible
    var tabbingMode: NSWindow.TabbingMode        // 默认 .disallowed
    var allowsFullScreen: Bool                   // .fullScreenPrimary
    var identifier: String?                      // 原样写 window.identifier
    var frameAutosaveName: String?               // 调用方既有名，原样使用
    var centersWhenNoSavedFrame: Bool            // 默认 true
    weak var delegate: NSWindowDelegate?
    static func newAutosaveName(_ suffix: String) -> String   // "cosmos.ui.window." + suffix
}
enum CosmosWindowFactory {
    static func makeHostingController<C: View>(rootView: C) -> NSHostingController<C> // [.toolbars, .title]
    static func makeWindow<C: View>(_ c: CosmosWindowConfiguration, rootView: C) -> NSWindow
    static func makeWindow<C: View>(_ c: CosmosWindowConfiguration, hostingController: NSHostingController<C>) -> NSWindow
}
extension View {
    func cosmosWindowTitle(_ title: String, subtitle: String = "") -> some View
    func cosmosWindowPrimaryAction() -> some View      // .glassProminent
}
```

工厂不显示窗口，不持有窗口，不含复用 / 关闭保护 / 未保存逻辑。

## 4. 风险

1. **尺寸 / 位置记忆**：现状无任何 autosave，迁移本身不丢位置。若第二批想新增记忆，必须注意 AppKit 限制：同一 autosave 名同一时刻只能被一个存活窗口占用（后者 `setFrameAutosaveName` 返回 false）。因此“每个对象一个窗口”的类型（笔记 / 项目 / 活动 / Artifact / 比较）不能共用一个固定名，建议只给单例型窗口（如无）使用，或保持 `center()`。本批工厂已支持传名但**测试未实际写 autosave**（避免写 UserDefaults），该路径为未覆盖项。
2. **窗口复用**：身份键、字典、identifier 全在 Manager。两处依赖 identifier 解析：活动详情 `UUID(uuidString:)`、其余 `windowWillClose` 取 rawValue 作键。**identifier 值必须逐字保持**，否则关闭后字典不清理，窗口无法再次打开。两处“复用时替换 contentViewController”（Review、资产详情）必须用 `makeHostingController`。
3. **未保存保护**：四个编辑窗口的 `windowShouldClose` 靠 `NSWindowDelegate`；工厂透传 `delegate` 但 `window.delegate` 是 weak，持有者必须仍是单例 Manager（现状如此）。toolbar 里的“取消 / 关闭”若保留，必须走 `performClose`（不是 `close()`），否则绕过保护。`.disabled(session.saving …)` 对 toolbar 项需单独加（见 §2.3）。
4. **标题双写**：`sceneBridgingOptions` 含 `.title`，SwiftUI 的 `.navigationTitle` 会覆盖 `window.title`；若视图没有声明 `.navigationTitle`，桥接是否会把初始标题清空**本批未实测**（测试不显示窗口）。第二批每个窗口接线后必须目视确认标题；安全做法是迁移时每个视图都声明 `.navigationTitle`。
5. **fullSizeContentView**：内容延伸到工具栏玻璃下。现有内容用 `VStack { header .background(.bar) … }` 的写法会与系统玻璃叠层；这些自绘 header / toolbar 迁走后才合适，**部分迁移（只换工厂不改内容）会出现顶部重叠**——建议每个窗口“工厂替换 + 内容迁移”同一提交完成。
6. **活动详情打开即执行本地恢复（既有 P1，本批不处理）**：`ZhuowangCampaignDetailView.onAppear` 调 `recoverLocalWorkflowIfNeeded()` / `migrateLegacyArtifactsIfNeeded()`（`:93`，函数体 `:1363`）。迁移 3.1 时窗口重建会改变 `onAppear` 触发时机（toolbar 桥接可能让视图多一次 appear），必须保持幂等并保证不因多次触发重复写。**3.1 接线前先确认该点，不要在窗口迁移中顺手改恢复逻辑。**
7. **测试面**：现有测试对 Manager 的 `chooseClose` / `openSessions` / `entries` 有依赖（编辑窗口测试），换工厂不得改这些成员的可见性与签名。
8. **未验证**：本批只验证了工厂造出的 NSWindow 属性；toolbar 实际呈现、玻璃样式、sheet 的 NavigationStack 效果均需第二批在真机窗口目视验证。
