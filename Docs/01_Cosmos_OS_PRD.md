# Cosmos OS 产品设计文档（PRD）

**版本：v0.1**  
**日期：2026-08-17**  
**项目仓库：Cosmos-Toolbox**  
**产品名称：Cosmos OS**

---

## 1. 产品定位

Cosmos OS 是一个面向个人长期使用的 macOS 原生 AI 工作操作系统。

它不是传统意义上的“系统优化工具”，也不是一个单纯的效率启动器，而是将工作、AI、学习、知识、项目和设备环境整合到同一个长期可演进的软件中。

第一阶段只服务一个核心用户，并围绕真实、高频、长期的工作流持续迭代。后续是否公开给其他用户使用，不作为当前版本的首要目标。

### 一句话定位

> 用一个长期可演进的原生 Mac 应用，把工作、AI、学习、知识和开发环境组织成一套属于自己的个人工作系统。

---

## 2. 产品目标

### 2.1 核心目标

Cosmos OS 第一阶段要解决五类问题：

1. **工作集中化**  
   把日常项目、活动策划、文档、流程图、原型和工作资料集中到统一工作入口。

2. **AI 工具集中化**  
   集中查看和管理 ChatGPT、Codex、Claude、Python、Git、Node、VS Code、Figma 等 AI / 开发工具的状态。

3. **学习持续化**  
   为 Python、Git、Swift、Figma、视频剪辑、Agent、MCP 等学习主题建立长期进度、笔记和复习系统。

4. **知识可检索化**  
   让历史项目、文档、Prompt、流程图、客服 FAQ、原型等内容不再依赖人工翻文件夹，而是可以统一搜索和复用。

5. **设备环境可维护化**  
   提供必要但克制的 Mac 环境检查、输入法管理、启动项检查和开发环境检测能力。

---

## 3. 非目标

Cosmos OS 当前阶段明确不做以下方向：

- 不做通用 Mac 清理大师。
- 不追求“清理垃圾、加速电脑”式营销功能。
- 不主动修改 SIP、系统安全策略或高风险隐藏参数。
- 不替代 Finder、Notion、GitHub、Figma、ChatGPT 等专业工具。
- 不为了功能数量而加入低频功能。
- 不在第一阶段追求多用户、团队协作、商业化和插件市场。
- 不在第一阶段自建复杂云后端。

---

## 4. 核心用户

### 第一阶段

单一核心用户。

产品的一切判断优先基于：

- 是否真正高频使用；
- 是否明显减少重复劳动；
- 是否降低工作切换成本；
- 是否方便长期维护；
- 是否比现有手工流程更简单。

### 后续阶段

当内部使用稳定后，再评估：

- AI 从业者；
- 内容运营；
- 产品运营；
- 独立开发者；
- 重度 Mac + AI 工具用户。

## 5. 核心模块

### 5.1 Dashboard

作用：统一入口和状态总览。

首期包括：

- 今日工作入口；
- 最近项目；
- 学习进度；

### 5.2 Zhuowang Workspace

定位：Cosmos OS 最重要的业务工作模块之一。

目标：

- 快速新建活动项目；
- 按省份和活动类型创建项目结构；
- 管理策划方案、客服文档、流程图、原型、素材、截图和版本；
- 复用历史活动模板；
- 统一检索历史项目；
- 对接后续 AI 生成能力。

首期建议支持：

**省份：**
- 河南
- 安徽
- 浙江
- 海南
- 广东
- 贵州
- 全国促活

**工作类型：**
- 福利中心活动
- 全国促活活动
- 竞猜活动
- 营销活动
- 客服 FAQ
- 活动规则
- 流程图
- Banner / 弹窗 / 营销物料需求
- 原型说明

未来目标：

- 一键生成标准项目目录；
- 调用固定模板创建策划案；
- 根据活动信息生成客服 FAQ；
- 生成流程图源文件；
- 记录 Figma / GitHub / 文档链接；
- 自动沉淀复盘信息。

### 5.3 AI Workspace

定位：AI 工具与开发环境状态中心。

首期检测：

- ChatGPT
- Codex
- Claude Desktop / Claude Code
- VS Code
- Figma
- Python
- Git
- Homebrew
- Node / npm
- uv
- DeepSeek Harness

后续可扩展：

- Docker
- Ollama
- MCP Servers
- API 环境变量存在性
- GitHub 登录状态
- SSH Key 状态

原则：

- 默认只检测状态；
- 不读取 API Key 明文；
- 不擅自修改用户配置；
- 修复操作必须可解释。

定位：跨项目、跨文档的统一知识检索层。

- Prompt

- 图片

第一阶段先做本地索引和元数据，不急于做复杂向量数据库。

---

### 5.7 Mac Optimizer

定位：辅助模块，不是主产品定位。

首期只做低风险、高价值功能：

- 输入法扫描；
- 输入法残留检查；
- 登录项查看；
- LaunchAgent 查看；
- 磁盘 / 电池 / 内存信息；
- 开发环境检查；
- Finder / Dock 常用设置。

明确避免：

- 高风险系统清理；
- 强制删除系统文件；
- 自动修改网络核心配置；
- 破坏系统安全策略。

## 7. 产品原则

### P1. 高频优先

优先开发每天或每周真正会用的功能。

### P2. 数据属于用户

尽量使用本地数据、本地文件和用户自己的 GitHub。

### P3. 原生优先

优先采用 Swift + SwiftUI + Apple 官方框架。

### P4. 安全优先

所有系统修改：

1. 明确展示；
2. 用户确认；
3. 可记录；
4. 尽可能可恢复。

### P5. 少即是多

不为了“看起来功能很多”而堆功能。

### P6. 工作流优先于单点工具

目标不是替代现有专业软件，而是把它们组织进更顺畅的工作流。

### P7. 长期维护优先

命名、架构、目录、版本和数据格式都要为未来数年迭代服务。

---

## 8. 数据原则

第一阶段默认本地优先。

建议数据层分为：

- App 设置：UserDefaults / AppStorage
- 结构化业务数据：SwiftData
- 文件：用户指定目录
- 项目元数据：本地 JSON / SwiftData
- GitHub：作为代码与部分文档的正式版本库

敏感信息：

- API Key 不存明文；
- 后续如需保存凭据，使用 Keychain；
- 不记录用户输入法内容；
- 不上传私人文档，除非用户主动选择。

---

## 9. 成功标准

Cosmos OS 第一阶段不是看 DAU，而看是否真正改变工作方式。

### V0.x 成功标准

- App 可以稳定运行；
- 形成可长期维护的导航结构；
- Zhuowang Workspace 可真实创建和管理项目；
- Learning Center 可持续记录学习；
- AI Workspace 可准确检测核心环境；
- 用户开始日常主动打开。

### V1.0 成功标准

满足以下条件即可认为 V1.0 成立：

- 连续使用 30 天；
- 至少 3 个模块进入真实日常工作；
- 数据稳定无丢失；
- 可以从 GitHub 完整恢复代码；
- 有版本记录和变更日志；
- 可以在新 Mac 上重新安装和恢复核心工作环境。
